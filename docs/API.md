# Integration contract v1

All API bodies and responses are JSON except CSV; dates are YYYY-MM-DD local Asia/Kolkata and months YYYY-MM. Errors: {error: string, code?: string}; 400 validation, 401 unauthenticated, 403 forbidden, 409 conflict, 429 rate limited. Mutations require X-CSRF-Token obtained from GET /api/session. API paths are matched case-insensitively by Express, so the session/CSRF middleware normalises the path before its prefix test; a mutation on a case-variant path still requires the token. Ten failed sign-ins for the same client and username within fifteen minutes return 429 with Retry-After. Responses set nosniff, frame-deny, no-referrer, a self-only Content-Security-Policy, and Cache-Control no-store for API responses. Credentials never committed. Roles admin/faculty; faculty scoped to assigned classes, admin unrestricted.

- GET /health returns {ok:true}.
- GET /api/session returns {user: {id,username,role}|null, csrfToken}; POST /api/login {username,password}; POST /api/logout.
- GET /api/classes returns {classes:[{id,name}]}; POST /api/classes {name}; GET /api/students?classId= returns {students:[{id,roll,name,department,active,startDate,endDate}]}; POST /api/students {classId,roll,name,department,startDate,endDate?}; PUT /api/students/:id same student properties with classId and enrollment dates; admin only mutations.
- GET /api/attendance?classId=&date= returns {classId,date,version,periods:[1..7 eligible],students:[{id,roll,name,statuses:{"1":"P"|"A"|"U",...}}]}. PUT /api/attendance {classId,date,version,entries:[{studentId,period,status}],reason?} atomic; status P/A/U; changes to previously saved marks including clearing require reason; stale version yields 409 and no writes. GET /api/history?classId=&date= uses the daily shape.
- GET /api/reports?classId=&month= returns {month,threshold,students:[{id,roll,name,working,present,absent,unmarked,percentage,complete,low}]} where percentage is number or null, low boolean only complete; an optional studentId filters to an individual student with enrollment in that class and month (otherwise 404). CSV GET /api/reports.csv accepts the same query and uses the same calculation and safe cells.
- GET /api/settings returns {threshold,calendar:[{date,periods:[1..7]}]}; PUT /api/settings {threshold}; PUT /api/calendar {date,periods:[1..7]}; admin only writes, rejecting changes invalidating recorded values. Unspecified weekdays 1..7; weekends none.
- GET/POST /api/users admin; POST /api/assignments admin; credentials submitted securely at setup, never hardcoded.

Enrollment is inclusive; no overlapping memberships; roll unique in class. Reports use full calendar month intersected with membership, even future dates. Working = P+A+U; strict unrounded threshold, rounded presentation, no definite low for incomplete/zero. Server rejects future attendance and ineligible period/enrollment. Saved marks remain if student deactivated; calendar/enrollment changes cannot invalidate marks. Account, enrollment and audit API details may be extended compatibly; document updates in docs/API.md.

Administrative account API: GET /api/users returns {users:[{id,username,role,active}]}; POST /api/users takes {username,password,role}; PUT /api/users/:id takes {username,role,active,password?}. PUT /api/classes/:id takes {name}. GET /api/assignments returns {assignments:[{userId,classId,username,className}]}; POST and DELETE /api/assignments take {userId,classId}. PUT student includes active and enrollment dates; transfer closes the previous enrollment on the day before its new effective date. Session token is also required for login. See backend-notes.md for additional details.
