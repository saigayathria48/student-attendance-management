# Demonstration walkthrough

Use an isolated database, the labelled synthetic seed and accounts obtained through the setup procedure in [README](../README.md). This walkthrough proposes actions; it is not an execution record. Select a past weekday with seven eligible periods for entry. The demo seed contains three students, not pre-filled attendance or the 154-period calculation fixture.

1. Sign in as the initial admin. Open **Administration** to create a faculty account and assign it to Demo Class. Record the account owner and secure credential reference separately; never record a password in evidence.
2. Open **Students**, choose Demo Class and load its students. Confirm the roll numbers, names, departments and enrollment dates. Add or edit a synthetic student, then try invalid or duplicate details and confirm the message and lack of an invalid record.
3. Open **Attendance**, select Demo Class and a past eligible date, then load the register. Mark all present, change individual periods to absent or unmarked, save, and reload. Check the intended seven controls and that a different date is unaffected. Correct a saved mark with a reason and review **Daily history** and correction history. A stale version requires reviewing the unsaved edits against a freshly loaded register before resubmission.
4. Open **Calendar & settings** as admin to review the 75% threshold and configure an exception on a separate date without saved attendance. For a holiday choose no periods; for a partial day choose the eligible subset. Verify the report denominator and incomplete status for the corresponding month.
5. Open **Monthly reports**, choose the class and month, and inspect each student row: Working, Present, Absent, Unmarked, percentage and status. Export CSV and reconcile the same month and totals. The selected full month is included, so unmarked future periods make the current month preliminary. A complete, independently verified fixture is needed for the four example percentages and threshold boundary checks.
6. Sign in as the assigned faculty and verify class access. An unassigned faculty account must not access another class. Restart the application and check the saved register again. Record outcomes separately from this walkthrough.
7. If Kubernetes and backup prerequisites are available, validate Pod replacement and an isolated restore in a dedicated test environment. Record the actual target, dataset, versions and results separately. Do not include secrets or personal data in artifacts.
